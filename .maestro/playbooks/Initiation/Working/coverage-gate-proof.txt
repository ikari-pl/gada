Notes worth preserving for future agents
------------------------------------------------------------------------
1. compiler/ baseline currently sits at 100.00% because this same task
   added unit tests for cmd/gada/main and internal/version/Describe to
   bring the bootstrap files above the 90% gate. (See main_test.go and
   version_test.go.) Phase 0 left those at 0%/0% because the prior agent
   deferred their tests to Phase 1; the gate's "revert and exit 0"
   verify clause forced the rest of the iceberg to land here.

2. main.go is now testable via an `osExit = os.Exit` indirection;
   TestMain_DispatchesViaOsExit swaps it on t.Cleanup so the test
   process is not actually torn down. This is the standard Go idiom
   for keeping main() thin while still covering its single dispatch
   line — without it main()'s 1 statement was uncovered and dragged
   compiler/ to 87.5% (8/9 lines), one statement under threshold.

3. The SKIP lines for compiler/internal/emit/ and
   compiler/internal/translate/ are EXPECTED at the foundation phase:
   those packages don't exist yet (they land in Phase 1). The gate
   correctly treats "no files matched the prefix" as a skip rather
   than a fail, since enforcing 95% on a 0-statement set is undefined.
   Once Phase 1 lands the first files under either path, the same
   thresholds will start enforcing automatically — no script change
   needed.

4. Threshold matching is overlapping by design: a file under
   compiler/internal/emit/ counts toward BOTH the emit/ threshold
   AND the parent compiler/ threshold. This is documented in
   tools/coverage_thresholds.toml and tools/coverage_gate.sh and
   is the reason the gate catches a deep regression even when the
   broad average looks acceptable.
